# 0002. Every idea follows five standard stages; agents own all tracking

- **Date**: 2026-10-06
- **Status**: Accepted
- **Issue**: #112

## Context
The owner works as product manager and delegates all implementation and tracking to AI agents. Several agents (Claude Code, Antigravity, Gemini) work on the repo, each reading its own instruction file and skill folder. Those copies had already drifted: a `mobile-deploy` fix landed in `.agents/skills` only. Ideas arrive half-formed, and without a fixed process some would go straight to code with no evaluation or design step.

## Decision
- Every issue labelled `idea` or `epic` gets five stage sub-issues, defined once in `tool/tracker/stages.json`: Evaluate → Explore alternatives → Specify → Implement → Verify & release. Project-specific work is task sub-issues under Implement. Stages are finished only through `tracker.py advance`, which also keeps the epic's board status right and closes the epic at the end.
- Ideas filed on GitHub get stages from the *Tracker* Action; ideas filed by agents get them from `tracker.py new`. `tracker.py sync` repairs anything either path missed.
- Agents do all tracking. The owner's touchpoints are the `needs-owner` and `human-only` labels, both shown in the board's **Needs you** view.
- `AGENTS.md` and `.agents/skills/` are the only sources of agent instructions. `CLAUDE.md`, `GEMINI.md` and `.claude/skills/` are generated by `tool/agents/sync.py`, and CI fails on drift.
- A **Backlog** status holds accepted-but-not-actionable items (future stages, parked ideas).

## Consequences
- Each idea creates six issues up front, so stage cards are hidden from the main Board view and shown as sub-issue progress instead.
- Small, obvious changes stay plain issues (`bug`, `enhancement`, `feature`) and skip the stages.
- The board's built-in "Item closed → Done" workflow is off and can't be enabled via the API; `tracker.py sync`/`close` do that job.
