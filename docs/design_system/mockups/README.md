# Design mockups

Approved mockups, kept as the visual reference for the spec they shaped. The spec in `docs/` is still the source of truth: a mockup shows intent, while the spec states tokens, sizes and behaviour. If they disagree, the spec wins, and the mockup gets a note.

- **File name**: `<epic number>-<short-kebab-title>.html`, for example `0047-canon-queue-layouts.html`.
- **Format**: one self-contained HTML file (inline CSS and JS; Google Fonts is the only external load). It opens straight from disk in a browser.
- **Content**: the approved option in every state the spec covers, drawn with the style guide tokens and switchable between dark and light. Use example content only.
- **When**: at the end of an epic's *Explore alternatives* stage, saved together with the decision record. The rejected options are described in the decision record and the stage issue; they don't need their own files.
- **Link** each mockup from its decision record and from the spec section it shapes, and add it to the index below.
